    System Documentation & User Guide

    What is Ward Notes?

    Ward Notes is an Offline-First Hospital Management & Clinical Electronic Health Record (EHR) Progressive Web Application. It is engineered so doctors, nurses, and ward staff can continuously admit patients, update vitals, and record clinical notes even during complete internet blackouts or Wi-Fi dead zones.

    Why Offline-First Matters in Healthcare

    • Zero Clinical Downtime: Traditional cloud HMS portals fail when hospital Wi-Fi drops in ICUs, basements, or rural clinics. Ward Notes never blocks a clinician from saving data.
    • Instant Local Response: All reads and writes happen in milliseconds against the device's local IndexedDB storage.
    • Automatic Background Recovery: Edits queue safely on the device and synchronize automatically via POST /api/sync the moment connectivity is restored.

    How It Works — End-to-End Sync Architecture

    5-Stage Data Pipeline
    1

    Offline-Capable PWA Shell

    The Service Worker (sw.js) caches HTML, CSS, JS, and icons locally so the app opens and reloads even with zero network connection.

    2

    Local Device DB (IndexedDB)

    Patient records are stored in browser IndexedDB with client-generated UUIDs, a dirty flag, and a base snapshot of the last server state.

    3

    Delta Sync Protocol

    When online, the client sends only modified fields + the base copy + its last seen sequence cursor (since) to POST /api/sync.

    4

    Field-Level 3-Way Merge

    SyncService.java compares each changed field against the server and base. Different fields merge cleanly; conflicting fields use Last-Write-Wins.

    5

    SQL Persistence & Audit

    Spring Boot commits merged records to the SQL patients table, increments syncSeq, and logs an immutable entry in audit_log.

    1. Patient Admission & Ward Directory

    Create, edit, and manage patient records including Full Name, Date of Birth (with automatic age calculation), Blood Group, Phone Number, Admission Status (Admitted, Active, Discharged), and detailed Clinical Notes.

    2. Offline Simulation & Outbox Queue

    Use the Simulate offline switch in the header to test network failure at any time. Records edited offline receive an amber ● pending tag and wait in the Outbox Queue until connectivity returns.

    3. Smart Field-Level Conflict Resolution

    If Nurse A updates a patient's Phone offline while Doctor B updates Notes on another device, both edits merge automatically. If both edit the same field, the latest timestamp wins and the conflict is reported transparently.

    4. Live SQL Audit Log & Soft Deletes

    Deletions use a synced deleted tombstone flag so removals propagate across all devices. Every CREATE, UPDATE, DELETE, and CONFLICT operation is permanently logged in the SQL audit_log table.

    Step-by-Step User & Demo Guide

    Quick Walkthrough
    Step 1
    Populate or Add Patients: Click Demo Data to load 5 realistic ward patients or click + Add patient to register a new record.
    Step 2
    Go Offline: Toggle Simulate offline in the top header. Notice the status pill turns red (● Offline) and the warning banner appears.
    Step 3
    Make Offline Edits: Edit any patient's status or clinical notes and save. Even if you refresh the browser while offline, your changes stay safe in IndexedDB with a ● pending badge.
    Step 4
    Reconnect & Sync: Turn off Simulate offline (or click Sync now). The outbox pushes changes to Spring Boot, updates the Seq # cursor, and logs the SQL audit trail.
